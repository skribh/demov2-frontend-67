# GitHub Pages Deployment Guide for Skribh

## Overview

This document explains how the Skribh website is deployed to GitHub Pages with a custom domain (skribh.com).

## Repository Structure

The repository has two main types of branches:

1. **Development Branches** (like `kaju-investors-page-changes`)
   - Contains the full React/Vite development environment
   - Includes source code in `/src` directory
   - Contains configuration files (`vite.config.ts`, etc.)
   - **Cannot be directly served** by GitHub Pages (will result in blank screen)

2. **Deployment Branch** (currently `main`, traditionally would be `gh-pages`)
   - Contains only the **built files** ready for production
   - Includes minified/bundled JS/CSS in `/assets` folder
   - Includes the `CNAME` file for custom domain configuration
   - **Can be directly served** by GitHub Pages

## Deployment Workflow

### How It Works

1. **Development Process**:
   - Make changes on a development branch
   - Test locally using `npm run dev`

2. **Build Process**:
   - Run `npm run build` to create optimized files in the `/dist` directory

3. **Deployment Process**:
   - The `gh-pages` npm package handles copying the built files to the deployment branch
   - The `predeploy` script automatically runs the build before deployment
   - When you run `npm run deploy`, it:
     - Builds the project
     - Creates/updates the deployment branch with built files
     - Pushes these files to GitHub
     - GitHub Pages then serves these files directly

### Deploy Command Explained

```json
"deploy": "gh-pages -d dist -b test-deploy"
```

- **gh-pages**: The npm package that handles deployment
- **-d dist**: Deploy the contents of the `/dist` directory (generated by the build)
- **-b test-deploy**: Deploy to the branch named "test-deploy" (remove this flag to use default "gh-pages" branch)

## Troubleshooting

### Blank Screen When Deploying

If you get a blank screen when GitHub Pages is pointing to a development branch:

1. Make sure GitHub Pages is set to use a branch that contains **built files**, not source code
2. Run the proper deployment process using `npm run deploy` from your development branch

### Testing Deployment Changes

To test changes to the deployment process:

1. Create a test branch from your development branch
2. Modify the deploy script to use a test branch (e.g., `-b test-deploy`)
3. Make a visible test change to verify the deployment
4. Run `npm run deploy` to deploy to the test branch
5. Check the repository settings to temporarily change GitHub Pages to serve from this test branch

### Current Setup

- Our main branch contains the built files (this is unusual but currently working)
- Development happens on feature branches
- To deploy, we run deploy from a development branch, targeting the main or gh-pages branch

## Recommended Practices

1. Keep the default branch as a development branch
2. Use `gh-pages` branch for deployment (standard practice)
3. Document deployments with descriptive commit messages
4. Use Pull Requests for reviewing changes before deployment
